## # Scope

### 做什么

1. `douyin_authorized_accounts` 新增 5 列 + 2 个检查约束（`authorization_status` / `authorization_version` / `authorized_at` / `last_success_at` / `last_authorization_error_at`）。
2. 发送边界可信定位：统一发送函数显式接收可信 `merchant_id`，按 `merchant_id + main_account_id + account_open_id + bind_status=1` 定位账号，删除发送后反查商户的授权用途。
3. 授权健康状态机：`UNKNOWN / AUTHORIZED / REAUTH_REQUIRED` 持久化、`WARNING` 动态派生；事故精确指纹分类 + 版本并发原子更新。
4. `REAUTH_REQUIRED` 本地预阻断：写失败流水、不调用 GMP、不重试、固定 409 错误合同。
5. 恢复闭环：复用 `bind-authorized-open-id`，原子递增 `authorization_version` 恢复 `AUTHORIZED`。
6. 前端预警闭环：现有账号徽标 + 发送区域横幅 + 复用现有重新授权弹窗，不新建页面。

### 不做什么（Decision 冻结排除项）

- ❌ 自动续期、token 存储、自动重放历史消息
- ❌ 发送流水新增 `merchant_id` 字段
- ❌ 页面外通知（短信/邮件/企业微信/NewCar）、后台定时任务、新增索引
- ❌ `raw_body_json` 结构化取证
- ❌ 方向 D（GMP 续期接口）相关任何建设
- ❌ M02 线索 / M04 企业微信 / M06 LAS 任何改动
- ❌ 修改 TOS / GMP 签名发送机制本身

## # Data Contract

### 表：`douyin_authorized_accounts` 新增列

| 字段 | 类型 | 空值/默认 | 语义 |
|---|---|---|---|
| `authorization_status` | `VARCHAR(32)` | NOT NULL DEFAULT `'UNKNOWN'` | `UNKNOWN` / `AUTHORIZED` / `REAUTH_REQUIRED` |
| `authorization_version` | `BIGINT` | NOT NULL DEFAULT `0` | 每次精确授权确认原子 +1 |
| `authorized_at` | `TIMESTAMPTZ` | NULL | 最近一次精确授权确认时间 |
| `last_success_at` | `TIMESTAMPTZ` | NULL | 最近一次成功 `send_msg` 时间 |
| `last_authorization_error_at` | `TIMESTAMPTZ` | NULL | 当前失效证据时间；重新授权后清空 |

### 约束（冻结命名，供启动检测与降级对照）

```text
ck_douyin_authorized_accounts_authorization_status
    CHECK (authorization_status IN ('UNKNOWN','AUTHORIZED','REAUTH_REQUIRED'))
ck_douyin_authorized_accounts_authorization_version
    CHECK (authorization_version >= 0)
```

### 状态机

| 状态 | 持久化 | 条件 | 发送行为 |
|---|---|---|---|
| `UNKNOWN` | 是 | 无足够健康证据（含存量迁移） | 允许 |
| `AUTHORIZED` | 是 | 存在成功发送或精确授权证据 | 允许 |
| `WARNING` | 否（派生） | 基础状态 `AUTHORIZED` 且进入预警窗口 | 允许并提醒 |
| `REAUTH_REQUIRED` | 是 | 当前授权代际已确认失效 | 本地阻断 |

`bind_status != 1` 的绑定门禁优先级高于上述状态，但不得改写授权健康字段。

### 字段生命周期（冻结）

| 事件 | status | version | authorized_at | last_success_at | error_at |
|---|---|---:|---|---|---|
| 存量迁移 | `UNKNOWN` | 0 | NULL | NULL | NULL |
| 普通绑定同步 / auth-redirect | 不变 | 不变 | 不变 | 不变 | 不变 |
| `send_msg` 成功 | 仅 `UNKNOWN`→`AUTHORIZED`，其他不变 | 不变 | 不变 | 单调取大 | 不变 |
| 确认授权失效（版本匹配） | `REAUTH_REQUIRED` | 不变 | 保留 | 保留 | 更新 |
| 精确重新授权 | `AUTHORIZED` | +1 | 更新 | 保留 | 清空 |
| 解绑 / 删除 / 普通重绑 | 保留 | 不变 | 保留 | 保留 | 保留 |

### 并发语义（Decision 强制约束 C1）

以下三种写入全部使用单条原子 SQL，禁止应用层 read-then-write：

1. 失效标记（条件更新）：

```sql
UPDATE douyin_authorized_accounts
SET authorization_status = 'REAUTH_REQUIRED',
    last_authorization_error_at = :now
WHERE id = :account_id AND authorization_version = :attempt_version
```

rowcount=0 即放弃（发送期间已完成更新代重新授权），不得覆盖新状态。

2. 精确重新授权（原子递增）：

```sql
UPDATE douyin_authorized_accounts
SET authorization_version = authorization_version + 1,
    authorization_status = 'AUTHORIZED',
    authorized_at = :now,
    last_authorization_error_at = NULL
WHERE id = :account_id
```

3. 成功发送（单调更新，仅 UNKNOWN 可升）：

```sql
UPDATE douyin_authorized_accounts
SET last_success_at = CASE
        WHEN last_success_at IS NULL OR CURRENT_TIMESTAMP > last_success_at
        THEN CURRENT_TIMESTAMP ELSE last_success_at END,
    authorization_status = CASE
        WHEN authorization_status = 'UNKNOWN' THEN 'AUTHORIZED'
        ELSE authorization_status END
WHERE id = :account_id
```

永远禁止 `REAUTH_REQUIRED → AUTHORIZED` 出现在成功发送路径。

### 事故精确指纹（Decision 强制约束 C2，与设计 V1~V4 逐字一致）

`classify_gmp_reauth_required(path, detail) -> bool`，同时满足：

1. `path` 严格等于 `/send_msg`；
2. `str(detail["upstream_code"]).strip()` 严格等于 `"400"`；
3. `detail["upstream_msg"]`（或 `upstream_payload` 中 `msg`/`message` 的同源值）经**首尾去空格 + 连续空白折叠**（`" ".join(text.split())`）后，严格等于：

```text
refresh_token 已过期，需要重新授权
```

禁止子串匹配、禁止依赖 `10010`、禁止泛化其他 `400`。其他 `400` 继续按现有 `upstream_business_error` 处理，不更新授权状态。

### 预警窗口（冻结）

`WARNING` 派生条件：基础状态 `AUTHORIZED` 且 `(now_utc.date() - authorized_at_utc.date()).days >= 23`（精确授权确认后第 23 个完整 UTC 日，即 D-7 阈值）。计算统一 UTC，前端仅按 `Asia/Shanghai` 展示。检测入口只有账号列表查询与发送前读取，不新增后台定时任务。

### 配置开关（Decision 强制约束 C4）

```text
DOUYIN_GMP_AUTH_LOCAL_BLOCK_ENABLED = parse_bool(env, default=True)
```

- 默认 `true`；非法值回落 `true`（沿用 `config.parse_bool` 回落语义，fail-closed）。
- `false` 仅关闭已有 `REAUTH_REQUIRED` 的本地预阻断（跳过预阻断分支直接调 GMP）；发送后的事故分类、状态记录、脱敏、原有发送门禁仍然生效。
- 该开关不允许启用自动重试或自动补发（无此代码路径）。

## # API Contract

### 错误合同（冻结）

```text
业务码：DOUYIN_GMP_REAUTH_REQUIRED
商户文案：该抖音账号授权已失效，请重新授权后再发送。
动作：reauthorize
HTTP 状态：409
```

人工发送固定响应（detail 恰好三键，不附加任何其他字段）：

```json
{
  "detail": {
    "code": "DOUYIN_GMP_REAUTH_REQUIRED",
    "message": "该抖音账号授权已失效，请重新授权后再发送。",
    "action": "reauthorize"
  }
}
```

定位失败合同（冻结）：

```text
业务码：DOUYIN_ACCOUNT_SCOPE_MISMATCH
固定文案：账号归属校验失败，已终止发送
HTTP 状态：403
不创建发送流水、不更新授权状态、不调用 GMP、禁止按 account_open_id 跨商户兜底查找
```

- 人工发送：现有 `require_douyin_account_for_merchant` 预检保持不变（403 `DOUYIN_ACCOUNT_FORBIDDEN`）。
- 后台三调用方：终态 `failed`，`failure_stage` / `last_error` 分别为 `douyin_gmp_reauth_required` 与 `douyin_account_scope_mismatch`，均不重试、不进入 `send_unknown`、不进 60 秒重试。

### `GET /accounts`（账号列表）

每个 item 新增 4 字段，全部固定返回、不得按状态省略：

| 字段 | 类型 | 空值语义 |
|---|---|---|
| `gmp_authorization_status` | 非空字符串 | `UNKNOWN/AUTHORIZED/WARNING/REAUTH_REQUIRED` |
| `gmp_authorized_at` | RFC 3339 UTC 或 `null` | 尚无精确授权证据 |
| `gmp_last_success_at` | RFC 3339 UTC 或 `null` | 尚无成功发送 |
| `gmp_last_authorization_error_at` | RFC 3339 UTC 或 `null` | 当前没有失效证据 |

- 既有 `authorization_status`（`authorized/unauthorized/invalid/deleted/not_found`）语义不变（V21）。
- 禁止返回 token、原始上游错误、`authorization_version`。

### `POST /accounts/bind-authorized-open-id`（恢复链路，Decision 强制约束 C5）

- 完全复用现有语义：登录态 + `auto_wechat:douyin_ai_cs` 权限 + `main_account_id` 一致 + `open_id` 精确一致 + 上游 `bind_status=1`。
- 未匹配（404 `DOUYIN_ACCOUNT_NOT_FOUND`）、非激活（409 `DOUYIN_ACCOUNT_NOT_ACTIVE`）、跨商户（403 `DOUYIN_ACCOUNT_ALREADY_BOUND_TO_OTHER_MERCHANT`）三条路径均**不得改写任一账号的授权健康字段**。
- 成功路径在既有 upsert 同事务内执行"精确重新授权"原子 UPDATE（见 Data Contract），成功后响应新增：

```json
{
  "gmp_authorization_status": "AUTHORIZED",
  "gmp_authorized_at": "<RFC3339 UTC>"
}
```

- `/auth-redirect`、`sync-bind-info` 不更新授权健康字段（维持现状，实施须验证未引入改动）。

### 本地阻断发送流水（冻结）

`REAUTH_REQUIRED` 预阻断时创建的 `douyin_private_message_sends` 行：

```text
status = failed
error_code = DOUYIN_GMP_REAUTH_REQUIRED
error_message = 该抖音账号授权已失效，请重新授权后再发送。（固定安全文案）
response_body_json = NULL
```

不调用 GMP、不进入 `send_unknown`、不自动重试。

## # Rollback

### 代码回退

- 新增列为 additive，旧应用可忽略新列继续运行（V27 已证）。
- 回退顺序：先回退应用代码，再评估数据库降级；应用回退时保留新增列与数据。

### 数据回退

- 数据库降级仅允许在新应用完全退出后执行，且必须另行审批（降级丢失授权投影）。
- 已写入的 `REAUTH_REQUIRED` 行与失效时间保留用于审计，不因回退删除。

### 配置回退

- `DOUYIN_GMP_AUTH_LOCAL_BLOCK_ENABLED=false` 仅关闭预阻断（受控兼容回退）；事故分类、状态记录、脱敏与原有发送门禁不随开关关闭而失效。该开关不提供自动重试/补发能力，回退不会引入重放。

## # Risk Checklist

- **权限**：`merchant_id` 唯一可信来源为 `RequestContext` 或已持久化的 run/task 字段；请求体传入的 `merchant_id` 一律忽略；前端不持有 internal token、不直连 9100（硬约束不变）。
- **隔离**：三元定位 + 跨商户 403，禁止按 `account_open_id` 跨商户兜底；同商户多账号状态独立（V18/V19）。
- **幂等**：三条写入全部原子 SQL；失效标记以 `authorization_version` 条件更新；重授权原子 +1；成功更新单调且永不 `REAUTH_REQUIRED→AUTHORIZED`（V15~V17 并发闭合）。
- **副作用**：本地阻断不调用 GMP、不进重试队列；失败流水固定安全文案、`response_body_json=NULL`；定位失败零写入；恢复链路拒绝分支零授权健康字段写入；开关关闭不引入重试/重放；SQLite 禁用态为显式日志声明、非静默内存回退。
- **已声明可接受风险（设计 §11，不构成阻塞）**：指纹依赖当前生产文本（上游改文案漏判不误判）；`authorized_at` 非平台签发时间；存量账号首期无提前预警；版本仅解决系统内并发；页面内提醒依赖商户进入工作台。
