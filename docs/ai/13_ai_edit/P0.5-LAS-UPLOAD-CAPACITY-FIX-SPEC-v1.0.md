## 1. Scope

### 做什么

1. **F1 前端上传大小前置校验**：文件选择后、发起 HTTP 请求前，检查 `file.size > 500MB`；超限文件不发送、不进入 nginx、不创建上传任务，给用户明确提示。
2. **F2 413 友好错误提示**：上传请求收到 HTTP 413（nginx HTML 413 或后端 `FILE_TOO_LARGE`）时，统一展示业务友好文案；不展示 nginx 错误、HTML 错误页或技术异常。

❌ nginx 自动治理 / `client_max_body_size` 自动化管理
❌ 容器内存限制 / 上传并发优化
❌ LAS 核心流程修改
❌ 数据库修改 / migration

## 2. Current Flow

```text
浏览器（MaterialLibrary 选择文件，accept="video/*"，无大小校验）
  → axios POST /ai-edit/materials/upload-tos（timeout 120000）
  → 宝塔 nginx（http 级 client_max_body_size，曾为 50m，2026-08-21 用户手动改 1000m）
  → 9000 FastAPI upload_material_to_tos（file.file.read() 整读后检查 500MB）
  → TOSUploader.put_object → 火山 TOS
```

| 前端无大小校验，超限文件白传到 nginx/后端才被拒 | [MaterialLibrary.tsx:123-139](frontend/src/features/ai-edit/pages/MaterialLibrary.tsx#L123-L139) |

## 3. Target Flow

### 成功路径（文件 ≤ 500MB）

```text
文件选择 → 大小检查通过 → 上传（原链路不变）
```

### 超限路径（F1，文件 > 500MB）

```text
文件选择 → 大小检查拦截 → 固定友好提示；不发送 HTTP 请求、不进 nginx、不创建上传任务
```

### 网络/服务器失败路径（F2，收到 HTTP 413）

```text
上传 → 错误识别（status === 413）→ 业务友好提示；不展示 nginx / HTML / 技术异常
```

## 5. API Contract Impact

**无 API 合同变化。**

- 请求合同不变：`POST /api/ai-edit/materials/upload-tos`（multipart，file + category）。
- 响应合同不变：成功 `TosUploadResult`；超限 413 `FILE_TOO_LARGE`。
- 前端识别规则（冻结，实施不可自行选择）：
  - `isMaterialSizeLimitError(err)` 判定 `err.response.status === 413`，即为大小限制错误。
  - 依据：后端唯一 413 即 `FILE_TOO_LARGE`；nginx 413 HTML 同为 status 413。单一状态判定覆盖 F2 全部两个来源。
  - 不引入 `getApiErrorCode` / `api/client.ts` 依赖，保持 uploadFeedback.ts 纯函数无依赖。

### 冻结常量（实施不可自行选择）

| 常量 | 值 | 语义 |
|---|---|---|
| `MAX_MATERIAL_UPLOAD_BYTES` | `500 * 1024 * 1024`（字节） | 与后端 `max_size` 逐字一致 |
| `MATERIAL_TOO_LARGE_TEXT` | `视频文件不能超过500MB，请压缩后重新上传` | F1/F2 唯一固定提示文案（Decision 建议文案冻结） |

### 冻结行为合同

**F1（前置过滤，MaterialLibrary.tsx `onTosUpload`）**：

- 拆分 `files` 为 `tooLarge`（`f.size > MAX_MATERIAL_UPLOAD_BYTES`）与 `valid`（其余）。
- 边界语义：`file.size == 500*1024*1024` 放行（与后端 `len(content) > max_size` 拒绝条件一致，两边均用严格大于）。
- `tooLarge.length > 0` → `toast.error(MATERIAL_TOO_LARGE_TEXT)`。
- `valid.length === 0` → 直接返回：不进入 `tosUploading` 态、不调用 `runUpload`、不调用 `load`、零 HTTP 请求。
- `valid.length > 0` → 按现有流程 `runUpload(valid)` 继续，其余行为不变。

**F2（上传后识别，uploadFeedback.ts）**：

- `runUpload` catch 中：`isMaterialSizeLimitError(err)` 为真 → `counts.tooLarge += 1`；否则沿用 `classifyUploadError` 现有 failed/unknown 分类。
- `summarizeUploadResults` 分支（按优先级）：
  1. `tooLarge > 0 && ok > 0` → toastText 现有 parts 追加 `，N 个文件超过 500MB 未上传`；errorText=null；callLoad=true。
  2. `tooLarge > 0 && ok === 0 && (failed > 0 || unknown > 0)` → errorText 为现有对应混合文案，末尾追加 `；N 个文件超过 500MB 未上传`；callLoad=false。
  3. `tooLarge > 0 && ok === 0 && failed === 0 && unknown === 0` → errorText = `MATERIAL_TOO_LARGE_TEXT`；callLoad=false。
  4. `tooLarge === 0` → 与现行为逐字一致（T1~T9 回归保障）。

## 7. Risk

| 风险 | 等级 | 说明 |
|---|---|---|
| 前端误判 | 低 | 仅依赖 `File.size` 标准属性，不读文件内容（零内存开销）；size 为 0 的流式对象按放行处理，不会误阻断 |
| 浏览器兼容 | 低 | `File.size` 为 File API 标准属性，所有现代浏览器支持；无新依赖 |
| 大文件边界 | 低 | 恰好 500MB（500*1024*1024 字节）放行，与后端 `len > max_size` 严格大于语义一致，无边界差 |
| nginx 限额低于 500MB 的漂移场景 | 低（已声明） | 若未来 nginx 回退 50m，<500MB 文件也可能收到 413，此时固定文案“不能超过500MB”会轻微夸大；Decision 已冻结统一文案，接受此偏差 |
| 误吞其他 413 | 低 | 已核实 `ai_edit.py` 中 413 唯一来源为 `FILE_TOO_LARGE`；其余接口 413 不经过本上传链路 |
